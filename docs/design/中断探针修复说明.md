# 中断探针修复说明（Ctrl-C 收尾）

> 主题：前台命令运行时用户 Ctrl-C，shell 丢弃命令列表 → 完成标记永不执行 → busy 卡死、`exec` 无限等待。
> 修复：`send()` 命中 `\x03` 后进入**中断周期**，周期定时器**周期性补发**中断探针（当前 seq 的裸标记命令）；完成判定只认当前 seq 标记，`^C` 回显与定时器均不作为完成依据。**定时器只重发探针，绝不"到点判完成"。**

## 1. 问题

- 完成标记法与命令同批下发：`<command> ;<markerCmd(seq)>`。前台命令运行中用户 Ctrl-C，shell 中断命令列表 → 追加的标记语句没执行 → 检测不到完成标记。
- `_remoteBusy` 不翻转，`exec` 永久等待；旧实现靠「TTY 回显 `^C`（`detectInterrupt`）+ 本次发过 Ctrl-C」判完成（`exitCode 130`），程序捕获/忽略 SIGINT 时会假完成。

## 2. 方案

1. **中断探针 + 周期补发**（`base-session.ts`：`_startInterruptCycle` / `_onInterruptTick` / `_stopInterruptCycle` / `_sendInterruptProbe` / `_composeProbe`，`send()` 中 `\x03` 触发）
   - 写完 `\x03` 后**立即**补发首条探针（t0，同一次 `send` 调用内，毫秒级）；若命令仍未结束，之后**每 `interruptProbeInterval` 秒**（配置项，默认 5）再补发一次（t0+5s、t0+10s…），直到命令结束。
   - 间隔来自配置项 `interruptProbeInterval`（秒，默认 5，见 §2.5）；常量 `INTERRUPT_PROBE_INTERVAL_DEFAULT_SEC` 为默认值，非法/缺失回退该默认。
   - 探针 = **换行符** + `_markerCmd(seq)` + **提交分隔符** `\r`。两个概念分开：换行（新起一行）用 `_ptyNewline()`（ConPTY 类 → `\r\n`，POSIX PTY → `\n`）；提交（让 shell 执行该行）沿用现状 `\r`。二者共用同一"是否 ConPTY 类"依据（`_ptyLineSep()` 返回 `\r` 即 ConPTY 类），**不硬编码 `\r\n`、不另立一套平台判定**（见 §7）。
   - shell 已回提示符 → 读探针执行标记 → 收尾；前台程序未死 → 字节留 tty 输入缓冲，待 shell 拿回控制权再读（**保持 busy、不误判**，下个 tick 继续补发）。
   - **定时器不判完成**：每次 tick 只做两件事——判命令是否仍在追踪（不在则停周期）、补发探针。完成只由当前 seq 标记触发。
2. **防抖（debounce）**：Ctrl+C 进入周期后，周期内再次 Ctrl+C（`_startInterruptCycle` 见 `_interruptTimer !== null` 即返回）不重启周期、不额外补探针。**但 `\x03` 字节仍由 `send()` 照常写入 PTY**（不吞按键，保留"连按两次退出"等程序行为）；只是探针逻辑被抑制。空闲期（无正在追踪命令）Ctrl+C 不进入周期。
3. **周期结束条件与清理**：命令完成收尾（`_completeRunning`）/ 运行上下文清理（`_clearRunningContext`，覆盖 SSH 断连等）/ 关会话（`close()`）/ 开始新命令（`_beginCapture`）→ `_stopInterruptCycle(reason)` 清定时器并清周期状态（幂等，重复调用无副作用）。
4. **防迟到污染**：`_probeSeqs` 记录已发探针 seq；`_stripProbeEchoes` 在 `_extractOutput` / `getRunningStream` / `readBuffer` 中按精确回显文本删除（覆盖迟到到达，不依赖定时器）。完成标记由 `stripMarkers` 统一去除（不限 seq）。seq 限定使旧 seq 标记永不结束后面的命令。中断命令输出在首个 `^C` 回显处截断。Raw 视图保留原始字节。
5. **间隔可配置**：配置文件 `~/.config/opencode/ssh-tool.jsonc` 顶层 `interruptProbeInterval`（单位**秒**，默认 **5**）。校验：仅接受正有限数；非数字 / NaN / ≤0 / 字符串 / null 等非法值一律回退默认 5（**不会**回退成 0 而关掉探针）。会话构造时转为毫秒传入 `BaseSession`（第 5 个构造参数 `_interruptProbeIntervalMs`）。改动配置需重建会话（重新连接）后生效。

## 3. 时序

```
用户 Ctrl+C ──► 写 \x03（PTY）──► 立即补发首条探针（t0）──► 启动周期（防抖：周期内重复 Ctrl+C 无效）
                                     │
                                     ├─ t0+5s ──► tick：命令仍在追踪 → 补发探针
                                     ├─ t0+10s ─► tick：补发探针
                                     └─ ...每 N 秒一次（N=interruptProbeInterval，默认 5），直到命令结束
命令结束（当前 seq 标记到达）──► 收尾 + 停周期
```

## 4. 改动点（`src/constants.ts` / `src/base-session.ts`）

| 位置 | 内容 |
|---|---|
| `config.ts` `interruptProbeInterval` | 中断探针补发间隔（秒，默认 5）：写入配置模板并校验（非数字/NaN/≤0/字符串/null → 回退 5） |
| `index.ts` | `loadConfig()` 后转毫秒传入 `SshSession`/`LocalSession` 构造器（`Math.max(1, round(sec*1000))`） |
| `constants.ts` `INTERRUPT_PROBE_INTERVAL_DEFAULT_SEC` | 默认间隔（5s）；实际间隔取配置值 |
| `base-session.ts` `_interruptProbeIntervalMs` | 构造器第 5 参（毫秒），默认 `INTERRUPT_PROBE_INTERVAL_DEFAULT_SEC * 1000` |
| `_interruptTimer` 字段 | 中断周期定时器（`setInterval`）；`null` = 不在周期内 |
| `_probeSeqs` 字段 | 已发探针 seq 集合（"探针已发"记录 + 迟到回显剔除依据） |
| `send()` | `\x03` → `_interruptSent=true`；写完 payload 后 `_startInterruptCycle()`（立即首发 + 按间隔 setInterval） |
| `_startInterruptCycle()` / `_onInterruptTick()` / `_stopInterruptCycle()` | 周期启动（防抖 + 空闲期不启动 + **立即首发**）、每 tick 判追踪后补发、停表并记原因 |
| `_ptyLineSep()` / `_ptyNewline()` / `_composeCommand()` | 提交分隔符（ConPTY → `\r`）与换行符（ConPTY 类 → `\r\n`、POSIX PTY → `\n`）的共用平台判定；`_ptyNewline()` 复用 `_ptyLineSep()` 的"是否 ConPTY 类"结论 |
| `_composeProbe()` / `_sendInterruptProbe()` | 探针文本组合（前导换行符 + 标记命令 + 提交分隔符）与单次补发（仅在 `_runningStartPos` 非空时；写完 `\x03` 立即调用一次） |
| `_stripProbeEchoes()` | 剔除探针命令回显（所有出现，跨命令生效） |
| `_waitCompletion()` / `_startBackgroundWatch()` | 删除 `^C` 回显完成分支，只认当前 seq 标记 |
| `_extractOutput()` | done 分支中断时截到首个 `^C`；`end<=0` 回退路径同样截断；末尾剔除探针回显 |
| `getRunningStream()` / `readBuffer()` | 剔除探针回显 |
| `_completeRunning()` / `_clearRunningContext()` / `close()` / `_beginCapture()` | 各清理路径停周期 |

**wire/proto**：纯 agent 侧逻辑，未改消息形状，`SERVER_PROTO_VERSION` 不变（保持既有未提交改动的 14）。

## 6. 边界与风险

- **探针被前台程序吃掉**：程序捕获/忽略 SIGINT 且读 stdin 时，探针字节在 tty 输入缓冲等待，不产生标记 → 命令**保持 busy、不会误判完成**；下个 tick（间隔 N 秒后）继续补发，直到程序退出、shell 读走探针或程序自身结束输出标记。
- **TTY 输入冲刷**：termios 默认在收到 INTR 时冲刷输入队列（`NOFLSH` 未置位），紧随 `\x03` 的立即探针字节理论上可能被一并冲刷。丢失只会延后一次收尾（保持 busy），且周期内按间隔反复补发，不会误判。
- **探针退出码**：取自探针执行时的 `$?` / `$LASTEXITCODE`，通常为 130 一类，仅作展示。
- **超宽折行命令**：`extractOutputStart` 未定位回显（end<=0）时回退整窗并截到首个 `^C`，与旧版输出语义一致；不影响完成判定。

## 7. 探针换行符修复（ConPTY 残影）

- **现象**：本地 WSL 会话（ConPTY 传输 + 内层 bash）中断时，raw 字节流出现被截断的探针碎片（如 `'\n<SSH_DONE:1:%s>' $?`，缺开头 `printf `），且 `_stripProbeEchoes` 按精确回显匹配**命不中** → 碎片泄漏进 transcript / 模型输出。
- **根因**：探针前导原用 `_ptyLineSep()`，本地会话返回裸 `\r`。ConPTY 下 `\r` 只是回车（光标回列 0、不换行），readline 会**重画整行**，字节流里留下被覆盖/截断的残影。
- **修复**：`_composeProbe` 前导改用 `_ptyNewline()`（ConPTY 类 → `\r\n`，POSIX PTY → `\n`），从干净新行开始；末尾提交分隔符沿用现状 `\r`。`_ptyNewline()` 的 ConPTY 判定复用 `_ptyLineSep()`，不重写平台分支。
- **为何碎片不再产生**：`\r\n` 让探针命令在完整新行上回显**一次且完整**，与 `_markerCmd(seq)` 逐字节相同 → 精确匹配命中并整体剔除。碎片是 `\r` 重画才有的字节，新写法根本不生成。
- **回归**：`_composeCommand`（普通命令、含多行包组）未改动，本地 ConPTY 内部分隔仍为 `\r`、POSIX 为 `\n`，尾部仍 `\r`。验证脚本 `.tmp/scratch/verify-probe.mjs` 断言：本地 `\r\n`/SSH `\n`、剔除无回显、回归字节不变。
