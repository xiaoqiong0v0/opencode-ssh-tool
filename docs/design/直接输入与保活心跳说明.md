# 直接输入与保活心跳说明

> 主题：两项新增行为——**Web 页面「直接输入」（焦点驱动）**与**保活/心跳（SSH 协议级 + WS 应用层）**。
> 核心口径：直接输入默认「命令框优先」、状态不持久化；保活与心跳均为**带外/应用层**消息，**绝不写入 PTY**，不污染终端输出与完成标记。

## 1. 直接输入（焦点驱动）

浏览器内直接向交互式程序（sudo 密码、REPL、vi 等）逐键输入。**默认关闭（命令框优先）**：页面初始焦点在命令框，按键留在浏览器，回车走 `exec` 提交命令。

| 行为 | 说明 |
|---|---|
| 启用 | 点击终端区域（transcript `#term` / raw `#xt`）或入口指示器 `#cmdKey` → 开启 |
| 关闭 | 焦点落到命令框/选择框等可编辑控件（xterm 内部辅助 textarea 除外）→ 自动关闭 |
| 发送通道 | 开启后按键经 `type:"send"` keystroke 通道发往终端，**不产生 `exec`、不写命令记录** |
| 按键内容 | 发送**真实控制字节**（Backspace=`0x7F`、Tab=`0x09`、Ctrl+字母=`0x01..0x1A`、导航键/ESC 引导序列），映射集中在 `web/src/keys.ts` |
| 不拦截 | 焦点在可编辑控件、浏览器快捷键（F5/F12/Ctrl+R/Shift+I…）、Cmd/Win 组合、端点离线时一律放行，不 `preventDefault` |
| 状态持久化 | **不持久化**；每次打开都从命令框优先开始（启动时清理旧的 `localStorage["directInput"]` 残留） |
| 离线/断线 | 入口叠加 `disabled`（`pointer-events:none`，不可点击）；按键一律不发送；`connStatus` 显示原因 |
| 可用性判定 | `wsUp && 当前选中终端 connected`；由「不可用→可用」（首次就绪/重连恢复）时重置为关闭并把焦点交还命令框，保证显示与实际一致 |

**与后端解码同口径**：前端发的是真实字节（不含反斜杠转义），`src/escapes.ts` 的 `decodeTerminalEscapes` 对真实字节逐字符原样通过，只解 `\xHH` / `\t` / `\r` / `\n`（`\n` 刻意解为 CR）/ `\\`。模型侧 `term_cli send "\x03"` 等转义文本走同一份规则，两条路径口径一致。

## 2. SSH 协议级保活

`src/session.ts` 的 SSH 连接（ssh2）启用协议级 keepalive，语义对应 OpenSSH 的 `ServerAliveInterval` / `ServerAliveCountMax`：

| 常量（`src/constants.ts`） | 值 | 语义 |
|---|---|---|
| `SSH_KEEPALIVE_INTERVAL_MS` | `20000`（20s） | 空闲时每 20s 发一次 `keepalive@openssh.com` 全局请求 |
| `SSH_KEEPALIVE_COUNT_MAX` | `3` | 连续 3 次无响应即判定连接死亡并断开 |

- 该请求是**连接层带外**消息（`keepalive@openssh.com` 全局请求），**不写入任何 channel/PTY**：不污染终端输出、不干扰完成标记。
- 空闲期防止路径上的 NAT/防火墙/远端 sshd 因空闲超时掐断长驻连接。
- 判死后 ssh2 置 `error.level="client-timeout"`，由既有 error/close 处理标离线并记日志（与普通断线日志可区分）。

## 3. WS 应用层心跳

server 与对端（agent / 浏览器）之间的 WS 连接加应用层 ping/pong 心跳，`server ↔ agent`、`server ↔ browser` **两条 WS 共用**同一套常量与逻辑。心跳是**应用层消息**，只在 WS 通道收发，**绝不写入 PTY**。

| 常量（`src/constants.ts`） | 值 | 语义 |
|---|---|---|
| `HEARTBEAT_INTERVAL_MS` | `25000`（25s） | server 每隔此时长向每条连接下发 `{type:"ping"}` |
| `HEARTBEAT_TIMEOUT_MS` | `10000`（10s） | server 发出 ping 后此时长未收到 `{type:"pong"}` → 判半开并 `terminate` |
| `HEARTBEAT_CLIENT_TIMEOUT_MS` | `HEARTBEAT_INTERVAL_MS * 2`（=50s） | 客户端超此时长未收到 server 的 ping → 判服务端半开，主动 close 并走既有自动重连 |

流程：server 定时发 `ping` → 对端回 `pong` 并刷新存活时刻 → 任一方持续静默超过各自超时即判**半开**（socket 已死但进程不知）并断开，对端随即收到 close、走既有自动重连，把「半开」变成「可发现 + 可自愈」。取 2 倍发送间隔作为客户端静默超时，容忍单次丢包/调度抖动。

页面参数由 server 渲染页面时注入：`__HEARTBEAT_INTERVAL_MS_VAL__` / `__HEARTBEAT_CLIENT_TIMEOUT_MS_VAL__`；页面未注入（旧缓存）时取 0 = 禁用心跳，不猜默认值。

## 4. 开发约束：改动注入内容须 bump `SERVER_PROTO_VERSION`

`SERVER_PROTO_VERSION`（`src/constants.ts`）标识 server 代码/协议版本，server 启动写入 `server.json` 的 `proto` 字段；`ensureServer` 发现既有常驻服务版本不符即杀掉旧进程重启。

- **改动服务端注入的页面模板（`web/src/index.html`）或 i18n 文案后必须递增该值。**
- 否则会出现「**旧注入 + 新前端**」错配：常驻旧 server 注入的 `__I18N__` / 占位符与新版前端期望的键不一致，页面渲染出 `undefined`。递增后旧进程被重启，注入随之刷新。

## 5. 涉及文件

| 文件 | 相关点 |
|---|---|
| `src/constants.ts` | `SSH_KEEPALIVE_*`、`HEARTBEAT_*`、`SERVER_PROTO_VERSION` |
| `src/session.ts` | ssh2 `keepaliveInterval` / `keepaliveCountMax`（带外，不写 PTY）；`client-timeout` 日志 |
| `src/server.ts` | 应用层心跳（下发 ping / 超时 terminate）；页面注入心跳参数 |
| `src/agent.ts` / `web/src/main.ts` | 客户端心跳检测（静默超时主动断开重连） |
| `web/src/keys.ts` | 按键 → 终端真实字节序列映射（纯逻辑） |
| `src/escapes.ts` | 转义文本解码（与前端真实字节同口径） |
| `web/src/main.ts` | 直接输入焦点驱动、入口指示器、keystroke 发送、状态不持久化 |
