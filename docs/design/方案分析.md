# opencode-ssh-tool 方案分析

> 对原始需求（`docs/requirements/需求说明.md`）的技术可行性分析、关键决策与风险清单。编码依据见 `docs/design/结构设计.md`。

## 1. 需求本质

opencode 内置 `bash` 工具每次调用都是全新进程，无跨调用状态。本插件的核心价值是**状态化远程 shell**：

- 连接一次，后续命令在同一会话执行
- 保留：cwd、环境变量、shell 变量、后台进程、sudo 凭据缓存
- 能处理 sudo 密码、vi、top 等**交互程序**
- 远程命令同样受 opencode 权限审批管控

**形态**：opencode 插件（npm 包），本项目提交 GitHub 发布 npm，TS 编辑后构建为 JS。

## 2. 技术选型评估

### 2.1 ssh2 + `client.shell({ pty: true })`

**结论：方案正确，且必须用 `shell()` 而非 `exec()`。**

| 方式 | 是否保留会话态 | 说明 |
|---|---|---|
| `client.exec(cmd)` | ❌ 不保留 | 每次调用起新 shell，cwd/环境全丢，不符合"长驻会话"需求 |
| `client.shell({pty:true})` | ✅ 保留 | 一个持久 PTY shell stream，命令通过 `stream.write(cmd + "\r")` 发送 |

`ssh2` 是 Node 生态最成熟的 SSH 库，支持 key / agent / 密码认证、PTY 分配，Windows 下无需特殊处理（PTY 由服务端分配，客户端只是收发字节流）。

### 2.2 参考插件模式

`@xiaoqiong0v0/opencode-playwright-tool` 的模式：**TS 工程（src）→ tsc 编译 dist → 作为 npm 插件加载**，状态化工具集 + 模块级共享状态 + `tool()` 定义，日志走 `@xiaoqiong0v0/opencode-plugin-logger`（按天滚动落盘）。本插件沿用全部四点：

- TS 源码 + `tsc` 构建，产物发布 npm
- 依赖全部在当前项目 `package.json` 声明、项目内安装（不污染全局配置）
- 4 个工具共享模块级 `sessions` Map
- 日志统一用 logger 插件（`createLogger("opencode-ssh-tool")`），记录工具调用供审计

> 依赖结构：`dependencies` = logger + ssh2；`peerDependencies` = `@opencode-ai/plugin`（宿主提供）；`devDependencies` = typescript + `@types/node` + `@types/ssh2`。详见 `结构设计.md` §2。

## 3. 关键难点与对策

### 3.1 命令完成判定（最大技术风险）

需求中"等待提示符返回"依赖**提示符匹配**，但该方案有硬伤：

- PS1 形态多变（`$`、`#`、`user@host:~$`、zsh 主题色），无法稳定正则匹配
- 命令输出可能恰好包含提示符样式文本 → 误判提前返回
- 无提示符的程序（vi/top/REPL）会直接卡死

**对策：哨兵标记法（sentinel）+ 静默窗口 + 超时三重兜底。**

1. **哨兵标记（主）**：执行时拼接 `command; echo __SSH_DONE_<rand>__`，读到哨兵行即认为命令执行完成。哨兵行之前的输出为命令输出，之后为新一轮提示符。
   - 用 `;` 而非 `&&`：即使命令失败也能读到哨兵，避免"命令报错 → 哨兵不打印 → 等满超时"的假死
   - `rand` 用随机数，避免与业务输出撞词
2. **静默窗口（辅）**：输出停止增长超过阈值（如 500ms）也视为完成，兜底哨兵因异常未打印的场景
3. **超时（兜底）**：默认 30s，超时返回已读部分，会话不挂死

### 3.2 交互程序识别

vi / top / sudo 等程序不结束、无哨兵，静默窗口会被误判或一直挂住。**对策：交互关键词检测**，检测到即**立即返回已读缓冲**并标记 `interactive: true`，提示模型用 `ssh_read` 配合。

关键交互触发词（服务端语言为英文时）：

- sudo 密码：`[sudo] password for`、`password for user:`、`Password:`
- 分页器：`--More--`、`(END)`
- 编辑器/全屏程序：vi 菜单、`top -`、`less`

### 3.3 PTY 回显与输出清洗

PTY 模式下 shell 会回显用户输入的命令本身（echo）。**对策**：返回前剔除命令回显行；同时对 ANSI 转义序列做最小清洗（`\x1b[..m` 等），保证模型读到干净文本。哨兵行的位置即回显结束的天然标记。

### 3.4 PTY 窗口尺寸

`{ pty: { rows, cols } }` 若不设置默认可能触发分页（如 `cat` 大文件 → `--More--`）。**对策**：设置较大行列（如 200x500），减少分页；残余分页由交互检测兜底。

## 4. 权限管控分析（核心）

### 4.1 `context.ask()` 语义确认

依据 `tool-definition.md`：`ask({ permission, patterns, always, metadata })`。
- `permission` 是字符串标识，opencode 用它记忆用户选择 → `:always` 即固化到权限配置
- `patterns` 传命令文本供展示

**注意**：`context.metadata` 是 `execute` 的函数（设置结果标题），`ask` 的 `metadata` 是普通对象，两者不同，勿混用。

### 4.2 决策：先黑后白再问

```text
命令进入 ssh_exec
  ├─ 命中 DENY 黑名单（高危）      → 直接拒绝，不进 ask
  ├─ 命中 ALLOW_READONLY 白名单    → 直接放行
  └─ 其他                         → context.ask() 让用户决定
```

- **高危命令硬拒**：`rm -rf`、`shutdown`、`reboot`、`mkfs`、`dd`、`DROP TABLE`、`TRUNCATE` 等。这些即使 ask 也风险过高，且 `:always` 固化后更危险，故不进 ask 直接拒
- **一般命令走 ask**：白名单外但非高危的，ask 弹审批

### 4.3 白名单绕过防护（方案补充点）

原方案白名单用正则 `ls|cd|cat|...` 匹配命令，存在**拼接绕过**漏洞：

```bash
ls; rm -rf /         # 命中 ls 白名单但实际删库
cat x > /etc/passwd  # 命中 cat 白名单但重定向写文件
$(danger)            # 命令替换
```

**对策：白名单必须整串全匹配 + 禁止 shell 元字符。**

1. 白名单按"整条命令"匹配，`^cmd args$`，不接受子串命中
2. 命令中出现 `;` `&&` `||` `|` `$(` `` ` `` `>` `<` 等**任何 shell 元字符 → 直接降级走 ask**（白名单不适用）
3. 由此 `ls` 单独放行、`ls; rm -rf /` 因含 `;` 自动走 ask → 用户在 ask 界面看到完整命令再判断

### 4.4 ssh_connect 也要审批（方案补充点）

原方案只对 `ssh_exec` 做权限管控，但模型可借 `ssh_connect` 连任意主机（如内网跳板、未知服务器）。**对策**：`ssh_connect` 同样走 `context.ask()`，用户确认 host/user/port 后才连接。

## 5. 认证方案

优先级（按需求"认证信息不硬编码"展开）：

1. **SSH key**（推荐）：默认用户 SSH 私钥（`id_ed25519` / `id_rsa`），或 SSH config 中的 Host 配置
2. **SSH agent**：agent socket（Unix）/ Windows OpenSSH agent
3. **环境变量密码**：`SSH_PASSWORD`（通用）或 `SSH_PASS_<HOST>`（按主机，host 大写）

约束：
- 密码只从环境变量读，不写入源码/配置/日志
- 日志与错误信息中对密码字段做过滤脱敏
- 认证超时 `readyTimeout` 设 10s，防止连不上的主机挂死

## 6. 会话生命周期与资源管理

| 场景 | 处理 |
|---|---|
| 模块级 `sessions` Map | key = `context.sessionID`（opencode 每会话唯一），跨调用共享 |
| 同 sessionID 重复 connect | 先 `close()` 旧连接再建新（需求已定） |
| 空闲超时 | 每次 exec 更新 `lastActive`，定期清扫超过 10 分钟未活动的会话并 close |
| 显式断开 | `ssh_disconnect` 清理连接 + 从 Map 删除 |
| 进程退出 | 注册 `process.on('exit')` / `beforeExit` 兜底关闭全部连接，防 opencode 退出后残留 |

## 7. 审计与输出限制

- 每次 `ssh_exec` 的返回值携带 `host` + `command` + `startTime/duration`，供 TUI 回溯（需求已定）
- 输出做截断保护（如单次返回上限 50KB / 5000 行），防刷爆模型上下文；超长输出提示用户用 `tail` 等方式分页

## 8. 风险清单

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| 1 | 命令完成判定不准 | 误判提前返回 / 假死 | 哨兵法 + 静默窗口 + 超时三重兜底 |
| 2 | 交互程序挂住 | 会话卡死 30s | 交互关键词检测 + 立即返回 |
| 3 | 白名单拼接绕过 | 高危命令被放行 | 整串匹配 + 元字符降级 ask + 先黑后白 |
| 4 | 多会话连接泄漏 | 资源占用 | 空闲回收 + 显式断开 + 进程退出兜底 |
| 5 | 认证失败/主机不可达 | 挂死 | `readyTimeout` 10s + 错误信息脱敏 |
| 6 | PTY 分页/回显噪音 | 输出被截断、含回显 | 大窗口 + 回显剔除 + ANSI 清洗 |
| 7 | Windows 下 agent 兼容性 | 认证失败 | 优先 key，agent/密码兜底，实测确认 |

## 9. 决策记录（ADR 摘要）

| 决策 | 内容 | 理由 |
|---|---|---|
| D1 | 用 `client.shell({pty:true})` 保持会话 | `exec()` 不保留状态 |
| D2 | 命令完成判定 = 哨兵法 + 静默窗口 + 超时 | 提示符匹配不可靠 |
| D3 | 权限 = 先黑后白再问 | 高危硬拒，一般问询 |
| D4 | 白名单整串匹配 + 禁止元字符 | 防拼接绕过 |
| D5 | `ssh_connect` 也走 ask | 防连任意主机 |
| D6 | 认证优先 key / agent，密码走环境变量 | 不硬编码凭据 |
| D7 | 空闲 10 分钟回收 + 进程退出兜底 | 防连接泄漏 |
| D8 | 形态 = npm 插件包（提交 GitHub 发布 npm），TS→JS | 需求定义，参考 playwright-tool |
| D9 | 日志走 `@xiaoqiong0v0/opencode-plugin-logger` | 按天滚动落盘，审计可回溯 |
| D10 | 工具集 6 个（+ssh_status / ssh_terminal） | 判断执行状态 + 弹窗查看记录 |
| D11 | 描述多语言（en 默认 / zh），环境变量 `SSH_TOOL_LANG` 切换 | 参考 playwright-tool toolLang |
| D12 | 弹窗 = 自包含 HTML 附件（data URL，可滚动） | opencode 无原生弹窗 API |
| D13 | 动画检测：连续输出 ≥5s 无哨兵/静默 → 返回 running，用 ssh_status 轮询 | 避免拿动画中间态当结果 |

## 10. 结论

方案整体可行，架构（ssh2 + PTY + 会话 Map + context.ask）成立。核心改进点集中在**命令完成判定**（哨兵法替代提示符匹配）与**白名单防绕过**两处。按 `结构设计.md` 编码即可落地。
