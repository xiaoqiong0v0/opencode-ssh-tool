## 1. 工程形态与交付物

**npm 插件包**：本项目提交 GitHub / 发布 npm，TS 源码编译为 JS。参考 `@xiaoqiong0v0/opencode-playwright-tool`。


- **本地测试**：编译产物挂载到测试项目的 **`.opencode/` 文件夹**（项目级插件目录，非全局）
- **发布**：本项目提交 GitHub / 发布 npm；使用方 `opencode.json` 的 `plugin` 数组引用
- **不在全局 opencode 配置目录做初始化与安装**，全部在项目内处理

## 3. 日志（logger 插件）

```ts
import createLogger from "@xiaoqiong0v0/opencode-plugin-logger"

const log = createLogger("opencode-ssh-tool", { enabled: true })

log.loaded()                              // 插件加载
log.info("连接成功 host=...")             // 普通信息
log.error("连接失败", err)                // 错误
log.hook("ssh_disconnect", "清理会话")    // 生命周期钩子
log.tool("ssh_exec", { command })         // 工具调用（含命令，供审计）
```

- 日志按天滚动落盘（默认目录可由 `createLogger` 第二参覆盖）
- **安全**：记录命令不含密码；认证信息（密码/私钥路径）不落日志
- 密码字段过滤：连接参数中的 password 一律不传给 `log.tool` / `log.info`

### 4.7 index.ts（插件入口）

```ts
import { tool, type Plugin } from "@opencode-ai/plugin"
import createLogger from "@xiaoqiong0v0/opencode-plugin-logger"
import { SshSession } from "./session.js"
import { T, getLang } from "./i18n.js"
import { loadConfig } from "./config.js"
import { startServer } from "./server.js"

const log = createLogger("opencode-ssh-tool", { enabled: true })
const lang = getLang()

export const sshSessions = new Map<string, Map<string, SshSession>>()
// 外层 key = opencode sessionID；内层 key = 终端名（默认 "default"）→ SshSession
// 一个 opencode 会话可建多个命名终端，同名重复创建先关旧终端

export const OpenCodeSshTool: Plugin = async (ctx) => {
  // 加载配置并启动 HTTP 服务（默认开启）
  const cfg = loadConfig()
  const server = cfg.server.enabled ? await startServer(cfg.server.port) : null
  log.info(`HTTP 服务 ${server ? "已启动" : "未启用"} port=${server?.port ?? "-"}`)

  return {
    tool: {
      ssh_connect: tool({ description: T.ssh_connect[lang], ... /* 见 §6.1，含 name */ }),
      ssh_exec: tool({ description: T.ssh_exec[lang], ... /* 见 §6.2，含 name */ }),
      ssh_read: tool({ description: T.ssh_read[lang], ... /* 见 §6.3，含 name */ }),
      ssh_status: tool({ description: T.ssh_status[lang], ... /* 见 §6.4，含 name */ }),
      ssh_disconnect: tool({ description: T.ssh_disconnect[lang], ... /* 见 §6.5，含 name */ }),
    },
  }
}

// 进程退出兜底：关闭全部连接
process.on("exit", () => { for (const map of sshSessions.values()) for (const s of map.values()) s.close() })
```

### 4.9 history.ts（消息对存储，持久化文件）

会话记录以 **命令+输出 一对**为单位管理，**全部存文件**（持久化，重启不丢），按对数限制：

```ts
export interface HistoryPair {
  command: string
  file: string          // 输出文件路径（持久化，每对一 JSON 文件）
  size: number          // 输出字节数
  ts: number
  seq: number           // 序号（文件顺序）
}

export class SessionHistory {
  constructor(cacheRoot: string, sessionID: string, maxMessages: number)
  append(command: string, output: string): void   // 写文件；超对数→删除最旧文件
  getPairs(): HistoryPair[]                       // 当前保留的所有对（旧→新）
  readOutput(pair): string                        // 从文件读输出
  totalPairs(): number
  dispose(): void                                 // 删除整个会话目录
}
```

- **目录**：`<cacheRoot>/<sessionID>/`，即 `~/.opencode/plugins-cache/opencode-ssh-tool/<sessionID>/`（与其他插件缓存结构一致）
- **每对一文件**：`<序号>-<ts>.json`（内容 `{command, output, ts}`），序号递增保证顺序
- 构造时扫描已有文件**恢复索引**（重启同 sessionID 可恢复历史）
- 超 `maxMessages`：删除**最旧**一对的文件
- `maxMessages` 最小 1（保留最新一对）
- 会话关闭 `ssh_disconnect`/进程退出 → `dispose()` 删除整个会话目录（随会话清理）

### 4.10 server.ts（本地 HTTP 服务）

- 启动 `http.createServer`，监听 `127.0.0.1:<port>`（port=0 → 系统随机分配）
- 路由：
  - `GET /` → 可滚动终端记录 HTML 页面（黑底绿字等宽，JS 定时轮询 `/api/transcript` 自动刷新）
  - `GET /api/status` → JSON：`{ port, sessions: [{sessionID, host, busy, connected}] }`
  - `GET /api/transcript?session=<id>` → 指定会话终端记录纯文本
  - `GET /health` → `{ ok: true }`
- 返回 `{ server, port, url }`；`close()` 关闭服务
- 页面默认展示所有会话，可切换指定 session

## 5. SshSession 关键行为

### 5.1 connect

- `client.connect({ host, port, username, readyTimeout, ...auth })` → `client.shell({ pty: { rows: 200, cols: 500, term: "xterm-256color" } })`
- `stream.on("data")` 累积到内部 buffer
- 认证失败 / 主机不可达：`readyTimeout` 10s 兜底，错误脱敏返回
- 密码不参与日志

### 5.2 exec / submit（哨兵法）

`ssh_exec` 默认**异步**（`submit`）：写入命令后立即返回，不等待、不占用上下文；后台哨兵监听在命令完成时把「命令+输出」对写入 history。模型后续用 `ssh_status`（完成否）/ `ssh_read`（history 模式 head/tail/limit 读历史，buffer 模式读实时缓冲）自由选择读不读、读多少。`waitResult=true` 时走同步 `exec`，等待哨兵返回完整输出（`_truncate` 截断保护）。

```
1. 从 sessions Map 取会话；不存在 → 返回错误提示先 ssh_connect
2. 生成哨兵 __SSH_DONE_<rand>
3. 组合命令：`<command>; echo <sentinel>`
4. stream.write(combo + "\r")；标记 busy = true
5. 异步 submit：立即返回 { submitted: true }（不等待）
   同步 exec：等待（上限 timeout）：
   - 读到 sentinel → 命令完成 → 输出 = 哨兵前内容（剔除回显、洗 ANSI）
   - 交互关键词 → 立即返回当前缓冲，interactive: true
   - 连续输出 ≥ ANIMATION_WINDOW_MS（5s）仍无哨兵/静默 → 返回 running: true（动画中），
     附当前已读缓冲，并启动后台哨兵监听（哨兵出现 → 收集输出进 history、busy=false）
   - 超时 → 返回已读部分，timeout: true，同样启动后台哨兵监听
6. 清理已消费缓冲；更新 lastActive；busy = false
7. 返回 { ok, output, interactive?, running?, timeout?, submitted?, host, command, duration }
```

> **动画检测**：长命令（进度条、spinner、apt 下载动画）会持续输出、静默窗口永不触发。此时不等待满超时，而是 5s 后返回 `running: true` + 部分缓冲，让模型调 `ssh_status` 轮询。后台哨兵监听翻转 busy 状态，命令真正结束后 `ssh_status.busy=false`，模型再 `ssh_read` 拿最终输出，避免拿到动画中间帧。

### 5.3 readBuffer

- 读取并清空当前会话未消费缓冲（供交互场景，如 sudo 密码后）

### 5.4 getStatus / getHistory

- `getStatus()`：返回 `{ connected, busy, pending, host, lastActive, duration? }`，供 `ssh_status`
  - `busy`：有命令正在执行（exec 进行中）
  - `pending`：缓冲未消费字节数
- `getHistory()`：返回 `SessionHistory`（命令+输出 消息对，按对数限制），供 HTTP 页面渲染

### 5.5 close

- `stream.end()` → `client.end()` → 从 Map 删除；幂等

### 6.3 ssh_read（读输出：buffer 实时 / history 历史对，多终端）

```ts
tool({
  description: T.ssh_read[lang],
  args: {
    source: tool.schema.enum(["buffer", "history"]).optional(), // 默认 history
    lines: tool.schema.number().optional(),                     // buffer：行数上限
    direction: tool.schema.enum(["tail", "head"]).optional(),   // history：默认 tail
    limit: tool.schema.number().optional(),                     // history：默认 10
    includeCommand: tool.schema.boolean().optional(),           // history：是否含命令
    name: tool.schema.string().optional().describe("目标终端名，默认 default"),
  },
  async execute(args, context) {
    // buffer：session.readBuffer() 读实时未消费输出（交互/轮询）
    // history：history.getPairs() 取前/后 N 对（N = max(1, limit)，不超过总对数）
    //   tail → 最后 N 条；head → 前 N 条；includeCommand 控制是否含 `$ 命令`
    // 返回：输出文本 + 浏览器 URL（HTTP 服务开启时）；metadata: { direction, returned, total, host }

```

> 合并了原 ssh_read（实时缓冲）与 ssh_terminal（历史对）的职责。HTTP 服务默认开启（配置 `server.enabled`，默认 true）；端口不设默认值（0=自动分配随机端口），模型经 `ssh_status`/`ssh_read` 获知实际地址，避免端口冲突。

## 7. 权限判定流程（核心）

```text
ssh_exec(command)
  ├─ sessions 无会话 ─────────────→ 返回"未连接，请先 ssh_connect"
  ├─ DENY 命中 ─────────────────→ 直接拒绝（返回"危险命令，已拒绝执行"）
  ├─ ALLOW_READONLY 命中 且 无 SHELL_META → 直接放行
  └─ 其他 ─────────────────────→ context.ask({ permission: "ssh_exec", patterns: [command], metadata: {...} })
                                   → 同意执行 / 拒绝返回"已拒绝执行"
```

```ts
export function isAllowed(command: string): boolean {
  if (DENY.test(command)) return false        // 先黑
  if (SHELL_META.test(command)) return false  // 元字符 → 降级 ask
  return ALLOW_READONLY.test(command.trim())  // 整串匹配
}
```
