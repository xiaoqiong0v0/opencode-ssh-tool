## 1. 工程形态与交付物

**npm 插件包**：本项目提交 GitHub / 发布 npm，TS 源码编译为 JS。参考 `@xiaoqiong0v0/opencode-playwright-tool`。

## 3. 日志（logger 插件）

```ts
import createLogger from "@xiaoqiong0v0/opencode-plugin-logger"

const log = createLogger("opencode-ssh-tool", { enabled: true })

log.loaded()                              // 插件加载
log.info("连接成功 host=...")             // 普通信息
log.error("连接失败", err)                // 错误
log.hook("ssh_disconnect", "清理会话")    // 生命周期钩子
log.tool("term_exec", { command | source+length }) // 工具调用；text 记命令，base64/file 只记来源与长度（不落明文）
```

- 日志按天滚动落盘（默认目录可由 `createLogger` 第二参覆盖）
- **安全**：记录命令不含密码；认证信息（密码/私钥路径）不落日志
- 密码字段过滤：连接参数中的 password 一律不传给 `log.tool` / `log.info`

### 4.5 session.ts（SshSession 类）

```ts
// SshSession 继承 base-session.ts 的 BaseSession（与 LocalSession 共用），构造器在基类上
export class SshSession extends BaseSession {
  constructor(sessionID: string, history: SessionHistory, name = "default", lang: Lang = "en")

  async connect(opts: { host: string; user: string; port?: number; password?: string }): Promise<ConnectResult>
  async submit(command: string): Promise<ExecResult>   // 提交后立即返回、不等待结果（命令仍在该终端前台执行）；后台 watch 收集输出进 history
  async exec(command: string): Promise<ExecResult>  // 同步等待结果（waitResult=true 用）；**无 timeout 参数、不设硬超时**（见 §5.2）
  async readBuffer(): Promise<{ ok: boolean; output: string; error?: string }>
  send(text: string): { ok: boolean; error?: string }  // 交互输入原样写入（供 term_cli send）
  async uploadFile(opts: Omit<UploadOptions, "sftp">): Promise<TransferResult>    // SFTP 上传（串行化，不占 PTY/busy）
  async downloadFile(opts: Omit<DownloadOptions, "sftp">): Promise<TransferResult> // SFTP 下载（同上）
  async precheckSyntax(command: string): Promise<ParseCheckResult>  // 远程发送前预检（bash/zsh/pwsh；独立 exec channel，见 §4.14）
  getStatus(): SessionStatus          // 供 term_cli status：connected/busy/pending 等
  getHistory(): SessionHistory        // 供 term_cli read（历史消息对）+ HTTP 页面渲染
  close(): void
  // 无 touch()：不做空闲自动回收（空闲回收相关常量已删除，无引用），lastActive 仅作状态展示
  // 内部：_composeEchoText、_composeCommand、_markerCmd、_awaitCompletion、_startFallbackWatch、_completeRunning、_clearRunningContext、_truncate、_appendBuffer
  // 说明：_awaitCompletion 是事件驱动等待（数据到达兑现，5s 窗口到点只兑现 running 转后台），_startFallbackWatch 是 ≥1s 的稀疏兜底（断连 + 极端漏判），不是轮询判完成
}
```

- 传输内部：`_enqueueTransfer`（每 `SshSession` 一条 Promise 链，失败不阻塞下一条）→ `_withSftp`（开通道也受总 deadline；通道 `error` 常驻监听，记日志 + `destroy()` + reject 本次传输；不改 PTY/连接状态）→ `transfer.ts`。
- `runSshTransfer`（同文件导出）：index 层固定 `instanceof SshSession → ask → run`，非 SSH 直接 `ssh_only`、审批拒绝 `denied`。
- `precheckSyntax`：bash/zsh/pwsh 且已连接时启用。bash/zsh 用 `client.exec("<shell> -n", { pty: false })`，命令经 stdin 写入后 EOF；pwsh 用独立 exec channel 启动解析侧车（`-NoProfile -NonInteractive -NoLogo -EncodedCommand <PS_SIDECAR_ENCODED_COMMAND>`），stdin 写 `base64(UTF-8 命令)\n!QUIT\n`，只读 `ERRCOUNT=` 响应行。不读写 PTY/`_buffer`/history、不翻转 busy、不改 `_connected`；超时 `destroy()` 通道并按 `{ok:true}` 放行（见 §4.14）。

```ts

```

- **存储层**：原始字节流保真写入 history（仅去完成标记 `stripMarkers`，不 trim/不删空行/不折叠换行/不动 ANSI）。web 端 HeadlessScreen（`@xterm/headless`）按终端语义忠实渲染。
- **模型层**：`toModelText()` 基于 `@xterm/headless` 终端模拟（处理光标定位/清行/退格/CR 覆盖/OSC/SGR/scrollback），读取最终屏幕各行后逐行去尾空白并剔除空行（write 异步，调用方需 await）。
- 已移除旧函数：`stripEcho`（纯文本正则，trim/删空行导致 PS1 首行丢失）、`cleanAnsi`（被 headless 屏幕解析替代）、`simulateScreen`（自研模拟器，被 `@xterm/headless` 替代）、`collapseCarriage`（被终端模拟器替代）、`genSentinel`/`stripSentinel`（随机哨兵，被序号式完成标记 `<SSH_DONE:nonce:seq:code>` + `stripMarkers` 替代）。
- 回显宽松匹配的 `ECHO_WIDE` / 行尾容忍 `TAIL_ANSI` 与探针回显剔除用的行首可见性判断 `normLine` 均复用 `src/ansi.ts` 的模式源（单一来源，见 §4.11），不再各自内联定义 ANSI 正则。

### 4.7 index.ts（插件入口）

```ts
import { tool, type Plugin } from "@opencode-ai/plugin"
import createLogger from "@xiaoqiong0v0/opencode-plugin-logger"
import { SshSession } from "./session.js"
import { LocalSession } from "./local-session.js"
import { T, getToolLang, getWebLang, tr } from "./i18n.js"
import { loadConfig } from "./config.js"
import { parseCliArgs } from "./cli-args.js"
import { ensureServer, type ServerResult } from "./server-manager.js"
import { precheckBeforeExec } from "./precheck.js"

const log = createLogger("opencode-ssh-tool", { enabled: true })

const sshSessions = new Map<string, Map<string, SshSession>>()      // 模块内部状态，不导出
const localSessions = new Map<string, Map<string, LocalSession>>()   // 本地/容器终端（term_cli local）
// 外层 key = opencode sessionID；内层 key = 终端名（默认 "default"）→ 会话
// 一个 opencode 会话可建多个命名终端，同名重复创建先关旧终端；同名在 SSH 与 local 之间也互斥（先清另一张 map 与对应 history，保证 resolveSession 无歧义）
// 会话按根会话 ID 路由（handleCliCommand 先 findRoot，主子会话共享终端）

export const OpenCodeSshTool: Plugin = async (ctx) => {
  // 加载配置并**不 await**地发起 HTTP 服务（默认开启）：服务启动慢/失败均不阻塞插件加载；
  // 需要 URL 的路径（doRead/doStatus 等）再惰性 await 保存的 Promise。
  const cfg = loadConfig()
  const toolLang = getToolLang(cfg.toolLang)   // 工具侧语言
  const webLang = getWebLang(cfg.webLang)      // 仅 Web 页面 UI 语言
  let serverStart: Promise<ServerResult> | null = null
  // 以下为节选：实际成功分支还会记录 httpUrl 并启动 startAgent(wsUrl, ...)；
  // 失败兜底结果还含 server/reused 字段，完整实现见 src/index.ts。
  if (cfg.server.enabled) {
    serverStart = ensureServer(cfg.server.port, listSessionEntries, cacheRoot(), webLang)
      .then((sr) => (log.info(`HTTP 服务 ${sr.url ? "已启动" : "不可用"} port=${sr.port ?? "-"}`), sr))
      .catch((e) => { log.error("HTTP 服务启动异常", e instanceof Error ? e : String(e)); return { url: "", port: 0 } })
  }

  return {
    tool: {
      // 单一 CLI 风格工具：args 为整条命令行字符串，由 handleCliCommand 解析分发子命令（见 §6）
      term_cli: tool({
        description: T.term_cli[toolLang],
        args: { args: tool.schema.string().optional().describe(T.term_cli_args[toolLang]) },
        async execute(args, context) {
          return { title: "term_cli", output: await handleCliCommand(args.args ?? "help", context) }
        },
      }),
      // 子命令：help | connect | local | exec | read | send | upload | download | status | disconnect
      // 旧的多工具模型（ssh_connect/ssh_exec/ssh_read/ssh_status/ssh_disconnect 各注册一个 tool）已废弃
    },
  }
}

// 发送前语法预检在 precheck.ts：index.ts / agent.ts 内部 import 后调用。
// **不得从 src/index.ts 具名导出 `precheckBeforeExec`**——否则 opencode 插件加载器会把该导出
// 误当插件工厂，报 config hook failed。仅导出 OpenCodeSshTool。

// 进程退出兜底：关闭全部连接（SSH + 本地/容器终端）
process.on("exit", () => {
  for (const map of sshSessions.values()) for (const s of map.values()) s.close()
  for (const map of localSessions.values()) for (const s of map.values()) s.close()
})
```

### 4.9 history.ts（消息对存储，持久化文件）

会话记录以 **命令+输出 一对**为单位管理，**全部存文件**（持久化，重启不丢），按对数限制：

```ts
export interface HistoryPair {
  command: string
  file: string          // 输出文件路径（持久化，每对一 JSON 文件）
  size: number          // 输出字节数
  ts: number            // 命令输入时刻
  endTs: number         // 命令完成时刻（标记出现时）
  exitCode?: number     // 退出码（完成标记读取；undefined = 未知，如语法错误/旧记录，勿补 0）
  seq: number           // 序号（文件顺序）
}

export class SessionHistory {
  constructor(cacheRoot: string, sessionID: string, maxMessages: number)
  append(command: string, output: string, startTs?: number, endTs?: number, exitCode?: number): void
  getPairs(): HistoryPair[]                       // 当前保留的所有对（旧→新）
  readOutput(pair): string                        // 从文件读输出
  totalPairs(): number
  dispose(): void                                 // 删除整个会话目录
}
```

- **目录**：`<cacheRoot>/<sessionID>/`，即 `~/.opencode/plugins-cache/opencode-ssh-tool/<sessionID>/`（与其他插件缓存结构一致）
- **每对一文件**：`<序号>-<ts>.json`（内容 `{command, output, ts}`），序号递增保证顺序
- `output` 存储**原始字节流**（仅去完成标记 `stripMarkers`，保留 ANSI 颜色/换行/空格/CR 覆盖，供 web HeadlessScreen 忠实渲染）；模型侧读取时经 `toModelText()` 即时清理
- 构造时扫描已有文件**恢复索引**（重启同 sessionID 可恢复历史）
- 超 `maxMessages`：删除**最旧**一对的文件
- `maxMessages` 最小 1（保留最新一对）
- 会话关闭 `term_cli disconnect`/进程退出 → `dispose()` 删除整个会话目录（随会话清理）

### 4.10 server.ts（本地 HTTP 服务 + WS 实时协议）

- 独立子进程启动（server-entry.ts），`http.createServer` 监听 `127.0.0.1:<port>`（port=0 → 系统随机分配），多 opencode 插件进程经 WS 作为 **agent** 注册共享
- `GET /health` → `{ ok: true }`；`GET /` → 终端记录页面；`GET /web/*` → 静态资源
- **实时协议（统一事件流，协议版本 `SERVER_PROTO_VERSION`，当前 22）**：
  - **agent→server（唯一数据源）**：`register`、`cmdStart{command,ts}`、`out{data}`、`cmdDone{exitCode,endTs}`、`raw{data,pos,reset}`、`transfer{task}`（传输任务元数据，仅 agent 可发）
  - **server→web**：`sessions`（json 去重）、`snapshot`（仅订阅/模式切换基线）、`diff{event:cmd|out|done}`、`meta{commands}`、`raw`、`transfer{task}`（广播，不回发 agent）、`transfer-remove{id}`（过期清理删除，不回发 agent）、`transfers{tasks}`（快照：`list` 回 `scope:"all"` 全量，`subscribe` 回 `sessionID` 对应会话**全部终端**任务；无任务也发空数组）
  - **web→server**：`list`、`subscribe{sessionID,name,mode}`、`setMode{mode}`、`exec`、`send`、`deleteTerminal`、`unsubscribe`
  - 详细协议定义与全路径清单见 `docs/design/消息协议重构设计.md`；传输任务结构与校验见 §4.13
- 会话列表由 `session-store.ts`（状态文件聚合）提供；历史记录供 snapshot 基线从文件读取（含运行中命令转 `cmd`+`run` 对）
- `busy` 推导：`streamBuf` 当前命令未 done、或排队序列 `seqHold` 保持中即 busy；**兜底仅「agent 连接消失」**（`agentBySession` 不含该 key → 强制置 done + 清 `seqHold`，防 agent 崩溃/退出卡死），**已无 `BUSY_TIMEOUT`（30s 无 out）自动置 done 的超时降级**——交互命令等待输入期间本就无输出，agent 仍在则 busy 必须保持（详见 `docs/design/消息协议重构设计.md` D4/D5）
- **Web 传输任务浮窗**（`web/src/index.html` `#transferToggle` / `#transferPanel` / `main.ts` `renderTransferPanel`）：header 按钮开关，默认关闭（开关状态 localStorage 记忆）；浮窗 `position:fixed` 右下角（`right:16px; bottom:72px`）、宽 `min(420px, calc(100vw - 32px))`、最大高度约 50vh，列表内滚动，**不参与 body flex、不挤压终端/命令框**，底部留出命令框空间。关闭后 header 按钮保留计数，可重新打开；切换会话/终端、任务更新仍刷新。只展示当前选中终端（会话 + 终端名）的任务（无选中会话/终端为空态），计数同口径；切换终端时列表切换为该终端任务，切换会话按新会话/终端快照刷新。任务按「running 优先，再按 `startedAt` 降序」固定排序；`transfer` 按 `id` upsert、`transfer-remove{id}` 删除本地行，`transfers{scope:"all"}` 全量替换、`transfers{sessionID,name}` 只替换该会话该终端并保留其他终端/会话。所有动态文本（终端名/路径/错误码）走 `textContent`，不拼 `innerHTML`；仅展示元数据。
- 返回 `{ server, port, url }`；`close()` 关闭服务

### 4.11 ansi.ts（ANSI 转义序列剥离，单一来源）

```ts
export const ANSI_SEQ_PATTERN = "\\x1b\\[[0-9;?]*[a-zA-Z]|\\x1b\\][^\\x07\\x1b]*(?:\\x07|\\x1b\\\\)|\\x1b[^\\x1b]"  // 模式源（无捕获组，可安全嵌入其他正则）
export function stripAnsi(s: string): string  // 剥净全部转义序列（CSI/OSC/其他 ESC），保留换行与可见字符
```

- **覆盖范围**：CSI（含 `?` / `;` 参数——既覆盖 SGR 着色，也覆盖光标/模式类序列，如 `\x1b[?25l` 隐藏光标、`\x1b[39;1H` 光标定位）、OSC（`ESC ] … BEL` 或 `ESC ] … ESC \`，窗口标题等）、双字节 ESC 序列（`ESC (`、`ESC =` 等）
- **单一来源**：`src/utils.ts` 的 `ECHO_WIDE` / `TAIL_ANSI`、提示符比较用的 `normLine`、语法错误检测（§5.6）全部复用本模式，不再各自定义 ANSI 正则——此前各处只容忍 SGR，真实 ConPTY 输出中的非 SGR 序列（`\x1b[?25l` 等）会漏剥，导致按行首判定失配
- 剥离不改变行结构（转义序列不含换行），但会改变字节偏移；故仅用于**判定类**匹配（如语法错误），定位类匹配（回显起止）仍在原始流上进行

### 4.12 transfer.ts（SFTP 文件传输，v1）

```ts
export type TransferErrorCode =
  | "exists" | "local_missing" | "local_is_dir" | "remote_missing" | "remote_is_dir"
  | "symlink" | "parent_missing" | "too_large" | "sftp_unavailable" | "timeout"
  | "io" | "unsupported" | "ssh_only" | "denied" | "tilde_user" | "remote_path_backslash"

export class TransferError extends Error {
  readonly code: TransferErrorCode
  readonly path?: string      // 错误回显路径
  readonly detail?: string    // 内部诊断（io 文案用）
}

/** 最小 SFTP 接口（与 ssh2 SFTPWrapper 结构兼容，测试注入 fake） */
export interface TransferSftp {
  stat / lstat / mkdir / rename / unlink / realpath
  createReadStream / createWriteStream / end / destroy
}

export async function uploadFile(opts: UploadOptions): Promise<TransferResult>
export async function downloadFile(opts: DownloadOptions): Promise<TransferResult>
export function parseTransferPositionals(positionals: string[]): { first: string; second: string } | null
export function assertTransferCapable(session: unknown): asserts session is TransferCapableSession
// UploadOptions/DownloadOptions: { sftp, localPath, remotePath, overwrite?, mkdir?, timeoutMs?, maxBytes?, abortSignal?, onProgress? }
// TransferResult: { localPath, remotePath, bytes, duration }（bytes 为实际读写计数，不含内容）

// index 层统一入口（session.ts）：instanceof SshSession → ask → run
export async function runSshTransfer<T>(params: { session: unknown; ask: () => Promise<void>; run: (s: SshSession) => Promise<T> }): Promise<T>
```

要点：

- **只走 SFTP**：`SshSession` 用现有 ssh2 `Client` 打开 SFTP subsystem（`client.sftp()`），不用 exec/scp/base64/PTY；每次传输结束关闭通道；通道 `error` 常驻监听（ssh2 ready 后已移除内部 onError），只记日志 + destroy 中止本次传输，不改 PTY/连接状态。
- **路径**：本地路径用 `expandLocalHome`（`path-utils.ts`，与 payload 共用）；远端 `~` / `~/...` 用 SFTP `realpath(".")` 展开（不经过 shell）；`~user` 返回专用 `tilde_user` 错误；Windows 远端盘符路径必须用正斜杠（`C:/dir/file`），反斜杠盘符路径返回 `remote_path_backslash`。
- **默认不覆盖（独占创建）**：上传默认远端 `createWriteStream({ flags: "wx" })` 直接写目标；下载默认先本地 `fs.open(path, "wx")` 再流式写入。目标已存在由 EXCL/EEXIST 原子拒绝（`exists`）；预检 `lstat` 只用于错误归类（区分 exists/目录/符号链接），不承担“不覆盖”的保证；不自动改名/备份。
- **overwrite 提交**：只有 `overwrite=true` 才写**同目录临时文件** `.name.opencode-ssh-tool-<随机>.part`，成功后 `rename` 到目标（同目录 rename，同一文件系统内原子）。若直接 rename 未成功且确认旧目标存在，再走“备份旧目标（`.bak`）→ 新文件就位 → 删备份”；已备份但新文件未就位的所有分支都尽力回滚旧目标（本地回滚不受传输 deadline 限制，远端用清理预算），回滚失败时错误 detail 给出备份路径。
- **父目录**：默认不建（`parent_missing`）；`mkdir=true` 时远端逐级 `mkdir`、本地 `mkdir -p`。
- **文件类型/大小**：`lstat` 判定；符号链接、目录、非普通文件拒绝；单文件上限 `MAX_TRANSFER_BYTES`（256 MiB），读写流运行时也按实际字节强制。
- **全链路超时**：`TransferDeadline` 覆盖开通道后的 realpath/stat/mkdir/读写流/rename；默认 `TRANSFER_TIMEOUT_MS`（10 分钟）。超时/外部中止会中止 SFTP 通道与流，提交前 `deadline.check()` 保证**不主动发起新的 rename/commit**（已发出的 rename 可能仍被执行）；无 `--overwrite` 时目标路径本身可能残留半截文件（重试报 `exists`），`--overwrite` 时可能残留 `.part`/`.bak`。
- **短读/短写**：`pipeWithLimit` 在写流 `finish`/`close` 结算时校验 `totalSize > 0 && bytes !== totalSize`，不一致报 `io`（`incomplete transfer`）并触发清理，**不得按 done 返回**（覆盖源提前结束、写流提前 close 等场景）。
- **串行化**：串行队列在 `SshSession._enqueueTransfer`，不占用 PTY/busy；`_withSftp` 在通道 error/超时后先中止 job 并等它真正 settle 再结算（兜底 `TRANSFER_JOB_SETTLE_TIMEOUT_MS` = 12s），保证同一会话下一个传输不早于前一个 job 结束；并发契约见 `docs/ASYNC.md`。
- **权限/日志**：`index.ts` 通过 `runSshTransfer` 固定顺序 `instanceof SshSession → ctx.ask(file_upload/file_download) → 传输`；日志 `log.tool` 只记方向/路径/实际字节/耗时/ok/错误码，字节不进模型上下文、终端历史、日志。
- **进度回调**：`onProgress(bytes,total)` 在拿到 `localStat`/`remoteInfo` 后先回调 `(0,size)`，之后每累计一块回调一次（空文件仅 `(0,0)`）；回调异常被吞掉，不中断传输。
- **仅 SSH**：`LocalSession` 没有 `uploadFile`/`downloadFile`；非 `SshSession` 返回 `transfer_err_ssh_only`，审批也不会触发。
- **参数**：`parseTransferPositionals` 要求恰好 2 个非空路径；多给/少给返回用法。

### 4.13 transfer-events.ts（传输任务事件）

```ts
export type TransferDirection = "upload" | "download"
export type TransferState = "running" | "done" | "failed"
export interface TransferTask {
  id: string; sessionID: string; name: string
  direction: TransferDirection
  localPath: string; remotePath: string
  state: TransferState
  bytes: number; total: number
  startedAt: number; endedAt?: number; errorCode?: string
}
export function parseTransferTask(value: unknown): TransferTask | null
```

- **只含元数据**：任务不含文件内容；`parseTransferTask` 只按白名单复制字段，未知字段被丢弃。
- **严格校验**：`id/sessionID/name/localPath/remotePath` 非空且长度受限（路径上限 `TRANSFER_TASK_PATH_MAX`）；`direction` 仅 `upload|download`、`state` 仅 `running|done|failed`；`bytes/total/startedAt/endedAt` 为安全非负整数；`errorCode` 为长度受限字符串。
- **产生时机（index.ts `doTransfer`）**：审批通过、`runSshTransfer.run` 开始后生成 `randomUUID` 并上报 `running`；完成发 `done`、异常发 `failed`。审批拒绝 / `ssh_only` 不产生任务（不伪造）。进度按 `TRANSFER_PROGRESS_THROTTLE_MS`（250ms）节流，完成/失败补最终值；无 agent 时静默。
- **server 侧**：`transferTasks: Map<id, TransferTask>` 只接受已注册 agent 的 `transfer` 消息（Web 伪造被忽略）；校验后广播给所有 Web 客户端（不回发 agent）。`list` 返回 `{scope:"all", tasks}` 全量快照；`subscribe` 返回 `{sessionID, tasks}`，按 `sessionID` 取该会话**全部终端**任务（不按终端 `name` 过滤，供 Web 切换终端时面板不丢任务）。快照过滤用独立条件（`sid` 只看会话、`name` 仅在传入时过滤），都没有也发空数组。
- **保留/清理**：`done`/`failed` 保留 `TRANSFER_TASK_TTL_MS`（10 分钟）；`running` 超过 `TRANSFER_TASK_STALE_MS`（10 分钟）无更新移除；清理周期 `TRANSFER_TASK_SWEEP_MS`，定时器 `unref` 不阻塞进程退出。每次移除广播 `{type:"transfer-remove", id}` 给 Web（不回发 agent），避免前端保留幽灵行。任务不写盘、重启即丢。
- **agent 断线收尾**：agent WS `close` 时，服务端按该连接 `register` 认领的会话键（`sid:name`）筛选仍为 `running` 的任务，改为 `failed`（`endedAt=Date.now()`、`errorCode="agent_disconnected"`）并广播；其他 agent/其他终端的任务不受影响。

### 4.14 precheck.ts（发送前语法预检）

`precheckBeforeExec(session, command, validate?, lang?, remoteTimeoutMs?)` 是 index（`term_exec`）与 agent（Web `run-exec`）共用的入口，两条路径**互不复用**：

- **本地/容器**（`isLocal=true`）：`stripCommandTail` 后调 `validateCommand`（`parse-check.ts`：常驻 pwsh 侧车 / 本机 `bash -n`、`zsh -n`），命中语法错误返回拦截文案。
- **SSH 远程**（`isLocal=false`）：仅当会话实现可选 `precheckSyntax`（`SshSession`，适配器为 bash/zsh/pwsh）时调用；**独立 SSH exec channel**，不占 PTY、不执行命令、不写 history/busy。
  - bash/zsh：跑 `<shell> -n`，命令经 stdin 写入；只有「非 0 退出码 + stderr 像语法错误」才拦截。
  - pwsh：复用本地 `parse-check.ts` 的侧车脚本/协议——`PS_SIDECAR_ENCODED_COMMAND` 作为 `-EncodedCommand` 参数启动侧车，stdin 写 `base64(UTF-8 命令)\n!QUIT\n`，stdout 找 `ERRCOUNT=...` 行并用 `parsePwshSidecarResponse` 转成 `ParseIssue[]`。候选按 `pwsh → powershell → powershell.exe` 依次尝试；只有拿不到协议响应且像「命令不存在」（127/9009 / not found / 不是内部或外部命令等）才换下一候选；`ERROR=1`、通道异常、超时、无响应一律 fail-open。
  - CMD：没有安全的 parse-only 通道，**明确跳过**（不预检、直接放行）。
  - 整段等待受 `REMOTE_PRECHECK_TIMEOUT_MS`（5s，多候选共享）约束；未实现、抛异常、超时、通道错误、非语法失败一律返回 `null`（fail-open，绝不误拦）。stdout/stderr 各限 `REMOTE_PRECHECK_OUTPUT_MAX`（16KB）；命令体超过 `REMOTE_PRECHECK_COMMAND_MAX`（32K 字符）直接放行。
- 拦截文案统一由 `formatSyntaxRejection` 生成（`precheck_failed` + ErrorId/行/列/片段）；远程错误片段优先取命令中对应行，否则取 stderr 首行，并限长 200 字符。ErrorId 为 `bash-syntax` / `zsh-syntax`，pwsh 保留解析器返回的真实 ErrorId（如 `UnexpectedToken`）。
- 行号解析兼容英文 `line N` 与中文 `行 N`（`parse-check.ts` 的 `parsePosixSyntaxLine`，本地/远程共用）。
- **边界**：只检查 shell 语法，不检查 Python/Node 等程序代码，也不替代执行后的 `detectSyntaxError`（§5.6）。

## 5. SshSession 关键行为

### 5.1 connect

- `client.connect({ host, port, username, readyTimeout, ...auth })` → `client.shell({ rows: PTY_ROWS, cols: PTY_COLS, term: "xterm-256color" })`（**40 行 × 120 列**，常量见 §4.1 / `src/constants.ts`；rows/cols 直接传给 `shell()`，不套 `pty` 对象。旧值 200×500 已废弃：超大 PTY 会让 zsh 按超大缓冲重绘，导致提示符/回显错位）
- `stream.on("data")` 累积到内部 buffer
- 认证失败 / 主机不可达：`readyTimeout` 10s 兜底，错误脱敏返回
- 密码不参与日志

### 5.2 exec / submit（完成标记法）

`term_cli exec` 默认**只提交、不等待结果**（`submit`）：写入命令后立即返回，不占用上下文；命令仍在该终端**前台**执行（期间该终端 busy，同终端下一条 exec 会被拒），后台标记监听（`_startFallbackWatch`）在命令完成时把「命令+输出」对写入 history。模型后续用 `term_cli status`（完成否）/ `term_cli read`（history 模式 head/tail/limit 读历史，buffer 模式读实时缓冲）自由选择读不读、读多少。`-w`/`waitResult=true` 时走同步 `exec`，等待完成标记返回完整输出（`_truncate` 截断保护）。**使用规则**：`-w` 会一直等到命令真正结束，长时间运行 / 需要 stdin / 交互的命令不要用 `-w`（会被一直堵住），改用默认 submit 再用 `term_cli status` / `term_cli read` 轮询。

```
1. 从 sessions Map 取会话；不存在 → 返回错误提示先 term_cli connect
2. 命令序号自增得 seq（_cmdSeq），按当前 shell adapter 生成完成标记命令 _markerCmd(seq)
   （zsh `printf '\n<SSH_DONE:<nonce>:seq:%s>\n' $?`；bash 同式不补尾换行；pwsh
   `Write-Output "<SSH_DONE:<nonce>:seq:$(if($?){0}elseif($LASTEXITCODE -as [int]){$LASTEXITCODE -as [int]}else{1})>"`
   ——退出码表达式由 adapter 生成，`$?` 优先、`$LASTEXITCODE` 兜底（`src/shell-adapter.ts:445`）；
   cmd `echo ^<SSH_DONE:<nonce>:seq:%errorlevel%^>`；无 adapter 时回退 POSIX printf 形式）；
   nonce 为会话级随机短串、seq 防残留标记误判
3. 组合命令 _composeEchoText：`<command> <语句分隔符> <标记命令>`（stmtSep：POSIX/pwsh 用 `;`，cmd 用 `&`；多行命令先用
   groupWrap 包组成一条）；_composeCommand 再按 `_ptyLineSep()` 改写换行并补尾部同一分隔符（ConPTY → \r，Unix PTY → _lineSep，通常 \n）
4. stream.write(combo)；标记 busy = true
5. submit（不等结果）：写入后立即返回 { submitted: true }（不等待，命令仍在该终端前台执行），输出由后台 watch 收集进 history
   同步 exec（waitResult=true）：_awaitCompletion **事件驱动等待**，**无 exec 级超时**：
    - 语法/解析错误（§5.6）→ 数据到达时判定（顺序：先认 DONE、再认 PROBE、最后判语法错误），等输出安静后按完成收尾（exitCode = null）
    - 读到完成标记 <SSH_DONE:<nonce>:seq:code>（detectLastDoneMarker 只认本会话 nonce + 当前 seq）→ 命令完成，退出码取自标记
      → 原始输出 = 标记前缓冲（stripMarkers 去标记，保真不动 ANSI/换行/空格）
    - 交互关键词 → 立即返回当前缓冲，interactive: true，并转后台 watch 继续等标记
    - 命令开始后固定 ANIMATION_WINDOW_MS（5s）仍未完成（与是否持续输出无关）→ 判定"长命令"，转后台标记监听；
      **exec 在内部等 busy 释放（事件驱动 `_busyWaiters`，busy 翻 false 时兑现，不做 200ms 轮询）**，命令真正结束才返回完整输出
    - Ctrl-C 中断 → `send()` 写完 `\x03` **立即补发首条中断探针**（`<SSH_PROBE:<nonce>:<seq>:<退出码>>`），之后按 `interruptProbeInterval`（秒，默认 5）周期补发（见 §5.7）；shell 回到提示符即执行探针并输出标记 → 按完成收尾，退出码取自探针标记。**`^C` 回显不再作为完成依据**（捕获/忽略 SIGINT 的程序同样回显 `^C` 但命令未结束，据此判完成会把后续命令喂进运行中的程序）；**不设「超时视为完成」兜底**（会误判 sleep 类静默命令）
6. 清理已消费缓冲；更新 lastActive；busy = false（排队序列中间命令按 _holdBusy 保持 true）
7. 返回 { ok, output, interactive?, submitted?, host, command, duration }
```

> **转后台检测**：命令开始满 5s（`ANIMATION_WINDOW_MS`）仍未结束（**是否持续输出无关**）即交给后台标记 watch 继续监听，`exec` 在内部等 busy 释放（`base-session.ts` exec 的 `running` 分支，事件驱动），命令真正结束后才把完整输出返回模型。**旧行为「5s 返回 `running: true` + 部分缓冲、让模型轮询多工具模型下的状态/读缓冲工具（现 `term_cli status` / `term_cli read`）」已废弃**（`ExecResult.running` 仅剩类型声明、exec 不再置位，`timeout` 字段亦不存在）；不设硬超时，长时间不结束由用户 Ctrl-C 干预（`send()` 立即补发中断探针 → 探针标记到达才收尾）。只有**不等待结果的 `submit`**（默认）才需要模型事后用 `term_cli status` / `term_cli read` 取结果。

### 5.6 语法/解析错误即时收尾（BaseSession / ShellAdapter）

shell 语法/解析错误（如 pwsh `ParserError`）使**整行命令作废**——与命令拼在同一行的完成标记也永不执行，标记法等不到完成信号（一直 busy、输出不落地）。故以 shell 报错本身作为完成信号。

`ShellAdapter` 新增 `readonly syntaxErrorRe: RegExp | null`（`src/shell-adapter.ts`）：

| shell | syntaxErrorRe | 说明 |
|---|---|---|
| pwsh | 行首 `ParserError:`（大小写敏感） | 报错首行即此 |
| zsh / bash | 行首 `syntax error` / `parse error`，以及中文 locale 的 `未预期的记号` / `未预期的文件结尾` / `语法错误`（容忍可选「路径 + shell 名 + 位置链」前缀；大小写不敏感） | 兼容 dash 的 `Syntax error` 大写形态；中文报错也能自动收尾，避免 `-w` 等完成标记挂死 |
| cmd | `null`（不识别） | 报错文案随系统语言本地化，按字节无法稳定识别；且 cmd 以 `&` 分隔命令，出错后同行标记**仍会执行**，标记法已完成判定，无需该信号 |

检测入口 `detectSyntaxError(adapter, buffer, fromPos)`：**先 `stripAnsi` 剥净窗口内全部转义序列，再按行首判定**（模式行首锚定因此无需再容忍序列；不带 `g` 标志，`test` 无状态）。收尾流程（`src/base-session.ts`）：

- `_checkCompletion` 先认真实完成标记（DONE），其次中断探针（PROBE），最后才跑语法检测；命中语法错误后不立即收尾，先等输出安静——停止增长达 `SYNTAX_QUIET_MS = 300` ms，或自首次识别达 `SYNTAX_MAX_WAIT_MS = 1_000` ms 上限
- 收尾走与正常完成一致的路径（history 落盘、`done` 事件、清 running 上下文、busy 按 `_holdBusy` 翻转）；无完成标记可读 → `exitCode = null`，输出窗口 = 回显结束 → 缓冲区末尾（含整段多行错误块）
- 语法路径下回显定位用 `extractOutputStart(..., first = true)` **首次匹配**：pwsh 错误块的 `   1 |  <命令>` 行会重印含标记的整行命令，末次匹配会落到该拷贝上，把 `ParserError:` / `Line |` 等错误块**前半裁掉**
- 语法错误收尾不补发探针：识别到行首语法错误后等输出安静 `SYNTAX_QUIET_MS`（硬上限 `SYNTAX_MAX_WAIT_MS`），到点直接按语法错误收尾；输出右界 = 缓冲区末尾，尾部最多多 1 行提示符噪音
- **不补发的原因**：语法检测可能被程序输出误判（行首 `ParserError:` / `syntax error`）；补发命令会写进仍在运行的程序 stdin（`cat >file`/REPL），且会提前收尾、丢弃迟到的真实完成标记。DONE/PROBE 分离只解决退出码覆盖，不解决注入
- 真实完成只认 `<SSH_DONE:...>`，中断探针只认 `<SSH_PROBE:...>`——两者严格分离；语法错误路径 `exitCode = null`
- 已删除 `_promptRef` / `stripTrailingPromptLine` / `stripPrompt` / `isPromptOnlyLine`：提示符形态不可可靠判断，不再做相等或模糊匹配

> **不变量（明确不做，勿后续"加固"）**：
> ① 不加「无完成标记 + 超时 = 命令已完成」式兜底——静默长命令（如 `sleep 60`、无输出的构建）会被误判为已完成；语法错误以外的"标记迟迟不出现"仍由用户 Ctrl-C 干预（`send()` 命中 `\x03` 后补发中断探针，探针标记到达才收尾；`^C` 回显本身不作为完成依据）。
> ② 不再用提示符行做相等/包含匹配；去掉判据后语法错误/Ctrl+C 输出尾部最多残留 1 行提示符噪音，接受该取舍（不为此重新引入脆弱判据）。

### 5.7 中断探针（Ctrl-C 收尾，`src/base-session.ts`）

**问题**：前台命令运行时用户 Ctrl-C，shell 因中断丢弃命令列表 → 原命令的完成标记永不执行 → `busy` 卡死、`exec` 无限等待。

**方案（事件驱动 + 低频兜底，不靠 200ms 轮询）**：

- 写完 `\x03` 后**立即补发首条探针**（同一次 `send` 调用内），之后按 `interruptProbeInterval`（秒，默认 5）周期补发，直至命令结束/关会话/开始新命令。
- 探针文本：`_composeProbe(seq)` = `_probeCmd(seq)` + `_ptyLineSep()`。`_probeCmd` 复用 `_markerCmd` 的退出码表达式，仅把 `DONE_TAG` 换成 `PROBE_TAG`，因此也是 `<SSH_PROBE:<nonce>:<seq>:<退出码>>`；DONE/PROBE 严格分离。分隔符由 `_ptyLineSep()` 统一给出（ConPTY → `\r`，Unix PTY → `_lineSep`，通常 `\n`），不硬编码；**不加前导换行**。
- shell 已回到提示符 → 读探针、执行标记 → 命令按 PROBE 标记收尾（中断退出码取自标记）；前台程序未死 → 字节留在 tty 输入缓冲，待 shell 拿回控制权再读（保持 busy，不误判）。
- 幂等：同一命令多次 Ctrl-C 多次补发，先到的当前 seq 标记胜出；周期内重复 Ctrl-C 不重启计时（`\x03` 字节仍照常写入）。仅在确有被追踪命令（`_runningStartPos` 非空）与连接仍有效时补发。
- 探针命令回显可能迟到落入后续命令窗口：`_probeSeqs` 记录已发 seq，`_stripProbeEchoes` 在 `_extractOutput` / `getRunningStream` / `readBuffer` 中按精确回显文本删除（无论何时到达）；DONE / PROBE 标记均由 `stripMarkers` 统一去除。seq 限定由 `detectLastDoneMarker` / `detectLastProbeMarker` 保证，旧 seq 标记不会结束后面的命令。Raw 视图保留原始字节。
- 中断命令输出在首个 `^C` 回显处截断（保留中断前程序输出）。
- 定时器**只负责周期性重发探针**，不做「到点判完成」；命令完成始终由当前 seq 的 DONE/PROBE 标记触发（`_checkCompletion` 事件驱动，`_startFallbackWatch` 仅 ≥1s 稀疏兜底**断连 + 极端漏判**，tick 调 `_checkCompletion(false)`）。

> **不变量**：`^C` 回显**不再作为完成依据**——捕获/忽略 SIGINT 的程序（mysql/REPL）同样回显 `^C` 但命令未结束，据此判完成会把后续命令喂进运行中程序；完成判定只认当前 seq 的探针/命令标记。

## 6. 工具定义

现实现为**单一 CLI 风格工具** `term_cli`（`src/index.ts`）：只有一个参数 `args`（整条命令行字符串，空则等价 `help`），由 `handleCliCommand` 先用 `parseCliArgs`（`src/cli-args.ts`）分词、再用 `node:util` 的 `parseArgs` 解析各子命令选项后分发。`parseCliArgs` 支持单/双引号、空白、未加引号的 token 与空字符串，并**保留双引号内的 `\"`（反斜杠与其后字符原样保留，不作为结束引号）**——避免 `send` 载荷里的 `\"` 被拆错、外层收尾引号漏进终端；`\n`/`\xHH` 等文本转义仍由 `decodeTerminalEscapes` 解码。注意 `\"` 会以“反斜杠+引号”原样送终端，`decodeTerminalEscapes` 不会把它还原成 `"`；最终是否解释由目标程序决定（如 MySQL 字符串会解释，需要字节精确的 heredoc 会保留反斜杠）。未闭合引号由 `parseCliArgs` 报错并在 `handleCliCommand` 直接拒绝发送；`splitCliArgs` 仅保留为兼容/测试用的 token 数组包装。

> **边界**：`parseCliArgs` 只处理 **CLI 外层**的单/双引号与反斜杠，不是目标 shell 的解析器。PowerShell 的反引号转义（如 `` `" ``）、cmd 的 `^"`、bash 的 `$'...'`/反引号命令替换属于**目标 shell 语法**，不能靠 CLI 分词器统一识别。命令同时含单双引号或依赖这些 shell 转义时，优先用 `exec/send --base64` 或 `--file`（见 §6.2），不要在外层引号里猜转义。

### 6.2 term_cli exec（执行，多终端）

```ts
// 用法：term_cli exec "<command>" [--base64 | --file <path>] [-n name] [-w]
// 位置参数 = 要执行的 shell 命令（多行命令整组为一条，见 §5.2）；-n/--name 目标终端名，默认 default
// -w/--waitResult 省略 = submit（提交后不等结果）；置位 = 等结果
// --base64 / --file：先经 resolvePayload() 解析成文本（二者互斥；file 读插件进程本机 UTF-8 文件，支持 ~ 展开）
//   解析失败 → PayloadError.code 映射 payload_conflict / payload_bad_base64 / payload_file_error；空文本 → cli_need_command
async function doExec(args, ctx) {
  // 1. payload = await resolvePayload(positionals.join(" "), { base64, file })；command = payload.text
  // 2. session = resolveSession(sessionID, name)；不存在 → 提示先 term_cli connect
  // 3. 权限判定（permission.ts createDecider → decide）：deny 直接拒绝；allow（白名单且无元字符）放行；ask → ctx.ask({ permission: "term_exec", patterns: [command], always: [`term_exec:${command}`], metadata: { title: command.slice(0, 60) } })
  // 4. 放行 → waitResult ? session.exec(command) : session.submit(command)
  // 5. log.tool("term_exec", { command | source+length, ok, submitted, interactive, running })；text 模式记 command，base64/file 模式只记 source+length；命中 DENY 同理不记明文
}
```

> **send 载荷**：`send` 同样接受 `--base64 | --file`（互斥）。默认 text 模式仍由 `decodeTerminalEscapes` 解释 `\n`/`\xHH`；base64/file 解析结果 `raw=true`，`session.send(text, { raw: true })` 跳过解码、逐字节原样发送。日志 `term_send` 在 base64/file 模式只记 `source` + `length`，回执用 `send_ok_source`（不回显内容）；text 模式保持 `describeSend` + `send_ok` 的 60 字符预览。载荷以 `-` 开头时用 `--` 终止选项（`exec -- "-x"` / `send -- "-n"`）。

### 6.6 term_cli upload / download（SFTP 文件传输，v1）

```ts
// 用法：
//   upload   <local>  <remote> [-n name] [--overwrite] [--mkdir]
//   download <remote> <local>  [-n name] [--overwrite] [--mkdir]
// 参数顺序固定：upload 第一个是插件进程本机路径、第二个是远端路径；download 反之。
async function doTransfer(direction: "upload" | "download", args, ctx) {
  // 1. parseArgs：-n/--name、--overwrite（布尔）、--mkdir（布尔）；缺 2 个位置参数 → cli_need_transfer_paths + 用法
  // 2. resolveSession(sessionID, name)；无会话 → not_connected
  // 3. 必须 instanceof SshSession；LocalSession（docker/wsl 等）→ transfer_err_ssh_only（不尝试传输）
  // 4. ctx.ask({ permission: "file_upload" | "file_download", patterns: [first, second],
  //             always: [`${permission}:${first}:${second}:ow=${overwrite?1:0}:mkdir=${mkdir?1:0}`],
  //             metadata: { title, overwrite, mkdir } })；拒绝 → transfer_denied（不打开 SFTP）
  //    always 键区分 overwrite/mkdir，避免“总是允许”普通上传后同路径 --overwrite 不再询问
  // 5. session.uploadFile({ localPath, remotePath, overwrite, mkdir, onProgress })
  //    或 session.downloadFile({ remotePath, localPath, overwrite, mkdir, onProgress })
  //    审批通过后先在 run 回调里生成任务 id 并上报 running；进度 250ms 节流；完成 done / 异常 failed
  //    （审批拒绝/非 SSH 不建任务）；无 agent 时静默
  // 6. 成功：upload_ok / download_ok（路径/字节/耗时）；失败：TransferError.code → transfer_err_* 文案（路径/上限/秒数由常量填充）
  // 7. log.tool("file_upload" | "file_download", { sessionID, name, local, remote, bytes, duration, ok, code? })
  //    不记录文件内容
}
```

- **远端路径**：绝对路径、相对 home 路径、`~/`（SFTP `realpath(".")` 展开，不经过 shell）；`~user` 专用错误；Windows 盘符路径用正斜杠（`C:/dir/file`），反斜杠盘符拒绝。
- **默认行为**：目标存在 → `exists`（默认 `wx` 独占创建；预检只用于错误归类，真正不覆盖由 EXCL/EEXIST 保证；不自动改名/备份）；父目录不存在 → `parent_missing`。`--overwrite` / `--mkdir` 才改变。
- **限制**：普通文件；目录、符号链接拒绝；单文件 256 MiB；**整个传输** 10 分钟 deadline（开通道/路径检查/读写/rename；超时不主动发起新的 rename/commit，已发出的 rename 仍可能被执行）。
- **实现**：见 §4.12（`src/transfer.ts`）与 `docs/ASYNC.md`（串行化/超时/清理契约）。

## 7. 权限判定流程（核心）

```text
term_cli exec "<command>" [-n name]
  ├─ sessions 无会话 ─────────────→ 返回"未连接，请先 term_cli connect"
  ├─ DENY 命中 ─────────────────→ 直接拒绝（返回"危险命令，已拒绝执行"）
  ├─ ALLOW_READONLY 命中 且 无 SHELL_META → 直接放行
  └─ 其他 ─────────────────────→ ctx.ask({ permission: "term_exec", patterns: [command], always: [`term_exec:${command}`], metadata: {...} })
                                    → 同意执行 / 拒绝返回"已拒绝执行"

term_cli upload | download
  ├─ 无会话 → 返回"未连接"
  ├─ LocalSession（docker/wsl 等）→ 直接拒绝（仅支持 SSH 会话），不打开 SFTP
  └─ ctx.ask({ permission: "file_upload" | "file_download", patterns: [local, remote], metadata: { title, overwrite, mkdir } })
        → 同意传输 / 拒绝返回"用户已拒绝传输"（不传、不落临时文件）
```

```ts
// 判定器工厂：内置正则 + 配置自定义正则（permission.deny / permission.allow 追加）
export function createDecider(customDeny: string[] = [], customAllow: string[] = []): CommandDecider {
  return function decide(command: string): Decision {         // "allow" | "deny" | "ask"
    const trimmed = command.trim()
    if (denyRegexes.some((re) => re.test(trimmed))) return "deny"   // 先黑
    if (SHELL_META.test(trimmed)) return "ask"                       // 元字符 → 降级 ask（防白名单拼接绕过）
    if (allowRegexes.some((re) => re.test(trimmed))) return "allow"  // 白名单整串匹配
    return "ask"
  }
}
```
