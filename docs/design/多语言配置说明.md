# 多语言配置说明（toolLang / webLang）

> 背景：`toolLang` 与 `webLang` 原本是两个独立配置，`12ab9bc` 将二者合并为单一 `lang`。
> 本文件恢复分离并明确边界：**`webLang` 只管浏览器页面 UI 文案，其余一律走 `toolLang`**。

## 1. 两类语言与作用范围

| 配置 | 环境变量 | 作用范围 |
|---|---|---|
| `toolLang` | `SSH_TOOL_LANG` | 工具 `description` / 参数说明、CLI 子命令输出、**agent/session 回传消息**（含显示在 Web 页面上的 exec 失败文本）|
| `webLang` | `SSH_WEB_LANG` | **仅浏览器页面 UI 文案**：标题、按钮、占位符、下拉标签等 |

会话内部产生的消息（上一条命令仍在运行 / 续行被拦截 / shell 探测超时 / 未连接）统一走 `toolLang`——它们既回给模型，也可能显示在 Web 页面，只能取一种语言，取工具语言。

## 2. 优先级

均为「环境变量 > 配置文件 > 默认 `en`」：

```
toolLang: SSH_TOOL_LANG > 配置 toolLang > "en"
webLang:  SSH_WEB_LANG  > 配置 webLang  > "en"
```

## 3. 配置示例

```jsonc
{
  "toolLang": "en",   // 工具描述 / CLI / agent·session 文案
  "webLang": "zh"     // 仅浏览器页面 UI
}
```

## 4. 向后兼容

旧字段 `lang` 仍可读取，命中时同时作为 `toolLang` 与 `webLang`（便于从合并版平滑迁移）。

## 5. 语言流转

```
index.ts        getToolLang(cfg.toolLang) ──┬─ tr(...) 工具/CLI 文案
                                            └─ new SshSession/LocalSession(..., toolLang) → BaseSession._lang
                                               （base-session / session / local-session 的 tr 用此值）
                getWebLang(cfg.webLang)  ──→ ensureServer(..., webLang)
                                            → server-entry --lang → renderPage + __I18N_JSON__（页面 UI）
```

## 6. 涉及文件

| 文件 | 改动 |
|---|---|
| `src/constants.ts` | 新增 `WEB_LANG_ENV = "SSH_WEB_LANG"` |
| `src/i18n.ts` | `getToolLang` / `getWebLang` 替代 `getLang`；新增 `cmd_busy` / `cmd_continuation` / `shell_probe_timeout`；删除死键 `web_running` / `web_auto_refresh` / `web_load_failed` |
| `src/config.ts` | 恢复 `toolLang` / `webLang` 两字段（兼容旧 `lang`）|
| `src/index.ts` | `toolLang` 用于 tr 并注入 session；`webLang` 传给 `ensureServer` |
| `src/server-entry.ts` | Web 语言回退改用 `getWebLang(cfg.webLang)` |
| `src/base-session.ts` | 构造新增 `lang`；`Not connected` / busy / 续行文案改走字典 |
| `src/session.ts` / `src/local-session.ts` | shell 探测超时文案改走字典 |
| `src/server.ts` | `JS_I18N_KEYS` 移除死键 |
| `web/src/main.ts` | `I18n` 接口与实际注入键对齐 |

## 7. 备注

- Web 端未纳入 `tsc` 类型检查（`tsconfig.json` 排除 `web`），`I18n` 接口与 `JS_I18N_KEYS` 曾出现漂移，已按实际使用对齐。
