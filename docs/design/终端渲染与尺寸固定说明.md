# 终端渲染与尺寸固定说明

> 本文件为变更说明文档，记录 raw（xterm.js）/ transcript 双通道近期修复：
> REPL 增量丢失、错误命令输出被裁、pwsh 输出顺序与 raw 错位、引号不闭合卡死、toBottom 遮挡。
> 基线文档 `结构设计.md`、`方案分析.md` 按本文件回填。

## 1. 问题与根因

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| G1 | REPL（如 `python3`）transcript 不回显增量输出 | web 输入框回车走 `exec` 消息，server `exec` 分支**无条件清空** `streamBuf`；但订阅者 `_txPos` 仅在 `cmdStart` 重置 → 增量 slice 为空 | `exec` 分支改为与 `cmdStart` 同语义：仅上一条**已完成**时清空，进行中（REPL 等待输入）保留累积 |
| G2 | 错误命令的输出被裁掉 | `extractOutputStart` 用全局最后匹配（`findLastEndOf`）定位回显结束；错误信息中含裸命令名时被误命中到 marker 之后 | 用**组合命令文本**（`command ;markerCmd`）定位回显结束，并加 `endBound` 限制在 marker 之前取最后匹配 |
| G3 | pwsh 完成标记落在命令输出**之前**，导致输出被裁 | `Write-Host` 直写 host 流，抢在 cmdlet 输出（经格式化器批量渲染）之前 | 标记命令改用 `Write-Output`（走 success 管线，与命令输出同序） |
| G4 | pwsh raw 画面错位/重复行 | PTY 固定 `PTY_ROWS` 行，而 xterm `FitAddon` 按容器实算行数（如 39）→ 二者不一致；PSReadLine 用**绝对光标定位**（`\x1b[40;42H`）越界 | 固定终端尺寸为 `PTY_COLS × PTY_ROWS`，xterm 不再自适应（见 §2） |
| G5 | 引号/反引号不闭合的命令 → busy 卡死 | shell 进入**续行等待**，追加的完成标记被当作续行内容 → 检测不到完成 | 提交前 `hasOpenContinuation()` 拦截（见 §3） |
| G6 | toBottom 按钮悬浮遮挡终端内容 | `.to-bottom-btn` 为 `position: fixed`（右下角悬浮） | 移入 header，`margin-left: auto` 走 flex 流式，不遮挡 |
| G7 | 多浏览器/重开历史时高度错位 | 曾用 resize 通道让 PTY 跟随 xterm：多 viewer 时"最后发送者生效"，PTY 行数可能大于某 viewer → 绝对定位越界；离线历史 raw 由 transcript 合成，含记录时的绝对定位（如 `\x1b[15;1H`），窗口更矮时被 xterm 夹到底部 | 固定尺寸、取消 resize（见 §2） |
| G8 | zsh raw 画面在标记后多出 `#` | POSIX 标记输出未以换行结尾，zsh 判定"上条输出未以换行结束"，补印 `PROMPT_EOL_MARK`（root `#`、普通用户 `%`） | **仅 zsh** 适配器标记补尾 `\n`；bash 无此机制，补了反而在 raw 多顶一行，故不补 |
| G9 | **超宽命令 Ctrl-C 后 busy 卡死**（命令已停、提示符已回，仍 busy=true） | 命令长度超过终端列宽时 readline 折行会重绘，回显字节里**多出一个边界字符**（如 `...libayatan` + `\r\n\x1b[39;120H` + `na-...`），`extractOutputStart` 的精确文本匹配必然失败（返回 -1）；而中断检测以 `echoEnd > 0` 为前置条件 → `^C` 永远不被检测 → busy 卡死 | ① 中断检测改为**只认"本次命令真实发送过 Ctrl-C"**（`_interruptSent` 由 `send()` 命中 `\x03` 置位，`_beginCapture`/`_clearRunningContext` 清除），不再依赖命令回显定位；② `extractOutputStart` 的字符间隙容忍"折行处重复前一个字符"，修复超宽命令输出提取把回显/提示符算进输出的问题 |
| G10 | **heredoc 命令卡死**（如 `cat >> ~/.bashrc <<'EOF' ... EOF`） | 三重叠加：① 多行拆分把 heredoc 拆成多条逐条执行，首行停在 heredoc 等待输入，后续行永不再发；② `stripTrailingComment` 在任意行的 `#` 处截断（正文注释行把命令切断）；③ 完成标记以 `;` 拼到分隔符行（`EOF ;printf ...`）→ `EOF` 不再被识别 | ① `splitByContinuation` 增加 heredoc 感知：`<<EOF` 起至分隔符行整体并入同一条命令；② `stripCommandTail` 只对**最后一行**去尾注释；③ 含 heredoc 时标记改用**换行**分隔（`_composeEchoText` 的 `sep`）；④ 续行检测跳过 heredoc 正文行，避免正文里的引号（如 `don't`）误判未闭合而拒绝命令 |

## 2. 尺寸策略（核心决策）

**固定 `120 × 40`（`PTY_COLS × PTY_ROWS`），取消 resize 通道。**

- PTY 创建即 `120 × 40`（SSH `pty` / 本地 `node-pty` 均用常量）；xterm 固定 `cols=120, rows=40`，不再按容器自适应。
- 尺寸恒定 ⇒ PTY 与 xterm 永远一致，PSReadLine 绝对定位不再越界；多浏览器、历史重开天然一致（无需取最小行数）。
- 曾被移除的中间态：`SERVER_PROTO_VERSION=10` 引入的 web→server→agent→PTY resize 通道（`scheduleResize`/`resize`/`run-resize`/`_resize`）及 `@xterm/addon-fit` 依赖，均已删除。

**布局规则**（`web/src/style.css` / `main.ts`）：

- `#xt` 为 flex 容器 + `overflow: auto`，`.xterm { margin: auto }`。
  - 页面够大：终端块**垂直居中**。
  - 页面偏小（不足 40 行）：容器滚动并**贴底**（保证命令行/光标可见），窗口 resize 后自动重贴底。
- `#xt > .xterm` 中 xterm 自身仍保留 scrollback 滚动（`scrollback: 2000`）。

## 3. 续行检测（各 shell 语义不同）

提交前拦截会让 shell 进入续行等待的命令，避免完成标记失效导致 busy 卡死。

| shell | 触发续行的情形 | 实现 |
|---|---|---|
| bash / sh / zsh | 未闭合 `'`、`"`、`` ` ``（命令替换）；行尾未转义 `\` | `posixOpenContinuation`（`src/shell-adapter.ts`）|
| pwsh | 未闭合 `'`、`"`；行尾 `` ` ``（转义符=续行）| `pwshOpenContinuation` |
| cmd | 未闭合 `"`；行尾 `^`（转义/续行）| `cmdOpenContinuation` |

- 入口：`ShellAdapter.hasOpenContinuation(command)`，在 `BaseSession.submit()` / `exec()` 中拦截，返回 `{ ok:false, error }`。
- 失败文本经 agent 以 `out{final:true}` 回传 web，transcript 可见失败原因。
- 注意：**不能**按引号统一配对处理反引号——POSIX 中反引号是命令替换定界符，pwsh 中是转义符（如 `"a`nb"` 合法，不可误判）。

## 4. 常量与协议

| 项 | 值 | 说明 |
|---|---|---|
| `PTY_COLS` | `120` | 列数，web 与 PTY 一致 |
| `PTY_ROWS` | `40` | 行数，web 与 PTY 一致 |
| `SERVER_PROTO_VERSION` | `11` | 本次删除 resize 通道后递增（10 为已废弃的 resize 协议）|
