# opencode-ssh-tool 插件开发需求

> 原始需求文档，**不可更改**。方案变更需写入 `docs/design/` 下的独立变更说明，并同步更新 `docs/README.md`。

## 需求

让 opencode 像人一样操作**长驻交互式 SSH 会话**：连接一次，后续在一个会话里连续执行命令，保留当前目录、环境变量、交互状态；且远程命令执行同样受 opencode 权限系统管控（类似内置 Bash 工具的审批）。

## 架构

- **形态**：opencode 插件, 提交github 发布到 npm,  ts 编辑后 构建为 js
- **底层**：`ssh2`（Node 库，持有一个 SSH 连接 + PTY 伪终端），保持单连接会话态
- **工具集**：状态化的 4 个工具，参考现有 `@xiaoqiong0v0/opencode-playwright-tool` `..\*` 的模式

## 工具设计

| 工具 | 入参 | 行为 |
|---|---|---|
| `ssh_connect` | `host`, `user`, `port?` | 建立 SSH 连接 + 打开 PTY shell，初始化 cwd 到登录目录，返回连接标识 |
| `ssh_exec` | `command` | 在**同一会话**执行命令，保留 cwd/环境，等待提示符返回，回显输出 |
| `ssh_read` | — | 读取当前会话缓冲区的未消费输出（用于交互提示场景） |
| `ssh_disconnect` | — | 关闭连接，清理会话态 |

关键行为：
- **PTY 模式**：分配伪终端（`{ pty: true }`），才能处理 sudo 密码、vi、top 等交互程序
- **会话态保存在模块级 Map**（key = sessionID），工具按会话取连接
- **超时**：每次 `ssh_exec` 设超时（默认 30s），超时返回已读部分，防止挂死

## 权限管控（核心）

`ssh_exec` 在执行前必须调用 `context.ask()`：

```ts
const ok = await context.ask({
  permission: "ssh_exec",
  patterns: [command],
  metadata: { title: `SSH 执行: ${command.slice(0, 60)}` },
})
if (!ok) return "已拒绝执行"
```

审批策略：
- **allowlist 默认**：只放行只读命令（`ls|cd|cat|grep|tail|head|ps|df|free|pwd|env|git status|echo|curl|wget` 等），在插件内配置 `ALLOW_READONLY` 正则
- **危险命令黑名单**：`rm -rf`、`sudo`（除非白名单允许）、`DROP TABLE`、`TRUNCATE`、`shutdown`、`reboot`、`mkfs` 等**默认拒绝**
- 白名单外的命令走 `context.ask()`，用户输入 `:allow` / `:deny` / `:always` 决定
- `:always` 可通过 opencode 的 permissions 配置固化（同 Bash 权限机制）

## 安全基线

1. **认证信息不硬编码**：从环境变量读取（`SSH_PASSWORD`、`SSH_PASS_<HOST>`、或走 `~/.ssh/config` / SSH agent + key），不写入插件源码、配置、日志
2. **不记录明文密码**：任何日志输出过滤密码类字段
3. **连接级保护**：会话空闲超时自动断开（如 10 分钟）；`ssh_disconnect` 在会话结束时调用
4. **命令可审计**：每次 `ssh_exec` 在元数据记录目标主机 + 命令，供 TUI 回溯
5. 提醒用户：已泄露的密码当已泄露处理，优先换 SSH key

## 文件结构

```
opencode-ssh-tool.ts
├── 常量：ALLOW_READONLY / DENY 正则
├── SshSession 类（ssh2 连接管理）
│   ├── connect(host, user, port, auth)
│   ├── exec(command, timeout)
│   ├── readBuffer()
│   └── close()
└── 导出插件：4 个工具 + 会话 Map
```

依赖 `ssh2`（npm 包）。本地插件如需外部依赖，在 `package.json` 声明，opencode 启动时自动 `bun install`。

## 实现步骤

1. `npm init -y && npm i ssh2`（或写入 package.json 依赖，由 opencode 自动安装）
2. 写 `opencode-ssh-tool.ts`）：
   - 最小可跑：`ssh_connect` + `ssh_exec` + `ssh_disconnect`，先不做权限管控，验证会话保持
3. 接入 `context.ask()` 实现权限审批
4. 加 allowlist / 黑名单
5. 测试清单 → 交用户实测

## 测试清单

- [ ] `ssh_connect` → 登录成功，cwd 为登录目录
- [ ] `ssh_exec("ls")` 连续 3 次，确认永不重连（同一会话）
- [ ] `ssh_exec("cd /var/log && pwd")` 后 `ssh_exec("pwd")` = `/var/log`（目录保持）
- [ ] 交互场景：`ssh_exec("sudo ...")` 触发密码提示 → `ssh_read` 配合
- [ ] 白名单命令不弹审批直接执行；`rm -rf` 被拒绝
- [ ] 白名单外命令弹 `context.ask()`，`:deny` 拒绝 / `:allow` 放行
- [ ] 长命令超时：`ssh_exec("sleep 60")` 30s 超时返回，不挂死会话
- [ ] `ssh_disconnect` 后连接释放

## 注意事项

- opencode 插件 API 参考 `~/.config/opencode/skills/opencode-plugin-dev/tool-definition.md`（`context.ask` 用于权限）
- 若 `context.metadata` 在某些版本为 `undefined`，用可选链 `context.metadata?.({...})`
- 单连接冲突：同一 sessionID 重复 `ssh_connect` 先 close 旧的再建新
- 平台：Windows 下 ssh2 PTY 由服务端分配，客户端侧无特殊处理
